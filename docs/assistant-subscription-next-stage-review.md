## اختيار المساعد والتكلفة المقترحة

مرشح التنفيذ OpenAI Responses API مع gpt-6-luna: الوثائق الحالية تصفه مناسبًا للأعمال المحددة ذات الحجم العالي ويدعم العربية ضمن الإمكانات متعددة اللغات. جودة الإجابات الدينية لم تُختبر حيًا؛ اختيار السعر ليس دليل جودة أو وصول الحساب للنموذج.

حسب سعر Standard للسياق القصير المقروء في2026-10-26:0.10$ للمليون input و0.50$ للمليون output. اقتراح أولي:25 جوابًا/مشترك/شهر وبحد3/يوم، مع كل طلب محدود3000 input و600 output بما يشمل reasoning. عند1000 مشترك يستخدم كل منهم25 مرة بالحجم الأقصى:25000 × ((3000×0.10 + 600×0.50)/1000000) =15$، وهامش5$ ضمن سقف20$. هذا سيناريو حسابي مشروط بالحدود والأسعار، وليس فاتورة متحققة أو استخدامًا غير محدود. لا يتضمن استضافة/ضرائب/عمولات المتجر/دعم أو تكلفة أدوات إضافية.

يلزم عدّ input بالمسار الرسمي /v1/responses/input_tokens قبل الطلب، وعدم تجاوزه. يُثبت max_output_tokens=600 وreasoning.effort=none وservice_tier=default، ولا Web/File Search أو صوت/صور مدفوعة. prompt_cache_options.mode=explicit دون breakpoints لمنع cache-write منفصل حسب الوثائق؛ أي تغيير تسعير أو نموذج يستلزم مراجعة معدل الحجز. لا استعمال characters/4 كضمان لميزانية العربية.

الحماية خادمية: حجز ذري لأقصى تكلفة قبل إرسال الطلب ضمن سجل شهر UTC عام، مع حد احتياطي أقل من20$ وحدود الحساب. UUID متفرد والحمولة ثابتة. لا تلقائية retry لطلب ربما حُسبت تكلفته؛ الفشل الغامض يحتفظ بالحجز إلى مصالحة. Usage الفعلي يُفحص ويُحاسب بدل الثقة بنجاح جهاز أو تقدير الحروف. عند نهاية السقف يُظهر توقف الخدمة، لا استمرار بلا إذن. لا يكفي تنبيه Dashboard؛ لا نعده سقفًا ذريًا.

المصادر من مكتبة حق المنشورة والقرآن القائم، باسترجاع محلي دون رسوم بحث. نعرض المصدر والنص الأصلي كما هو من الكتالوج، ونميز الشرح الآلي عن النص؛ لا ينشئ النموذج آية/حديثًا داخل مصدر موثوق ولا مراجع غير موجودة. عند غياب الدليل تظهر محدودية المصدر. يلزم تقييم عربي ومجموعة أسئلة/رفض ومراجع مختبرة قبل الإتاحة للمدفوعين. الخصوصية: store=false دون ادعاء Zero Data Retention؛ لا إرسال اسم/بريد أو معرّفات حساب صريحة.
