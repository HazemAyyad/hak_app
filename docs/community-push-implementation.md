# P15 — إشعارات رسائل حق بالخلفية — 2026-10-27

استكمال للنقص التنفيذي الموثق بعدP13. أضيف تكامل FCM/Apple APNs للمحتوى العام المعتمد في رسائل حق، منفصلًا عن أذان الصلاة والتذكيرات المحلية. الرايات والحسابات والملفات ما زالت مؤجلة بقرار المستخدم، دون إرسال إشعار حقيقي أو إنشاء حساب Firebase أو Run/APK أو نشر.

## التطبيق

- خيار مستقل في رسائل حق، مع حالة صريحة «بانتظار تهيئة الخدمة» وإعادة المحاولة عند فشل الإذن/الشبكة. لا طلب إذن أو اشتراك FCM عند أول بدء لتثبيت لم يختر الخدمة. التهيئة الأصلية الأساسية من ملف المنصة قد تحصل عند البدء لتدعم استقبال عملية مغلقة؛ auto-init الخاص بـMessaging معطل افتراضيًا.
- تفضيل عام للجهاز للمحتوى العام، لا يرتبط بحساب خاص ولا يدخل النسخ الاحتياطي. الاشتراك في topic ثابت `haq_public_messages_v1` بعد اختيار المستخدم وإذن النظام وقدرة الباك. لا رفع بريد أو اسم أو رمز حساب حق إلى خدمة Push.
- تثبيت firebase_core3.15.2 وfirebase_messaging15.2.10 بسبع اعتماديات جديدة فقط، دون تغيير إصدارات الاعتمادات السابقة أو رفع iOS13/Android24. فُحص شرط iOS13 من podspec للحزمتين. اختيار الإصدارات يحافظ على الحد الحالي؛ دمج SDK وتجميعه وفحصه ما زالا بوابة جهاز/منصة.
- موضوع FCM مخصص للمحتوى العام فقط. الإشعار عنوانه «رسائل حق» ومتن عام؛ لا نصوص منشورات أو بيانات خاصة أو روابط خارجية. الضغط يفتح دليل الرسائل ويعيد تحميل المنشورات الحالية؛ منشور محذوف/مخفي لا يتحول إلى محتوى محلي قديم.
- يتحقق مسار الفتح من kind/route/id، ويمنع تكرار فتح الصفحة من الحدث نفسه، ويعالج النقر عند بدء بارد أو تطبيق بالخلفية. فشل API لا يمنع فتح الدليل من إشعار مستلم سابقًا. إلغاء الاشتراك متسلسل ومحفوظ؛ فشل تأكيد الإلغاء لا يعرض نجاحًا. قد يصل إشعار كان قيد النقل قبل الإيقاف.
- استقبال إشعار مرئي بالخلفية يعتمد payload النظام الأصلي وليس Timer أو Dart isolate أو التطبيق مفتوحًا. لا صوت Push تلقائي؛ قناة مستقلة صامتة، مع بقاء اختيار الصوت داخل القسم المفتوح مستقلًا. لا وضع خلفي دائم أو تشغيل GPU.
- Android: قناة/أيقونة أصلية وتعطيل auto-init/Analytics افتراضيًا، وتطبيق Google Services plugin فقط إن وُجد ملف التفعيل. iOS: entitlements للتطوير/الإنتاج وremote-notification/fetch، وتهيئة native Firebase عند وجود plist داخل bundle مع إبقاء التذكيرات المحلية وتمرير بقية استجابات الإشعارات إلى super. لا نبني المنصات لإثبات أن هذه التهيئة اجتازت الربط الأصلي.

## الباك

العقد في `C:/laragon/www/haq-foundation/docs/religious-push.md`. source migration جديد بجداول `religious_push_state` و`religious_push_outbox` فقط؛ لم ينفذ على قاعدة فعلية.

- حد بدء تفعيل يمنع إرسال أرشيف قديم؛ ترسل رسائل channel=message المنشورة/المجدولة وحان موعدها وغير المنتهية، دون مسودات/مخفية/قصص/أدعية حسابات.
- إيصال فريد لكل منشور وclaim خادمي يمنع عمل العاملين على نفس الإرسال. يعاد التحقق من صلاحية المنشور وقت المعالجة. الرد المؤكد المقبول يسجل معرّف FCM؛ هذا قبول مزود لا إثبات وصول هاتف.
- إعادة محدودة حتى5 محاولات لردود429/5xx مع انتظار. انقطاع HTTP أو claim قديم يصبح uncertain ولا يعاد تلقائيًا؛ لا ادعاء exactly-once من مزود خارجي. notification tag/APNs collapse-id ثابتان لكل منشور لتقليل التكرار. TTL لا يتجاوز يومًا أو انتهاء المنشور.
- أوامر الجدولة تُسجل فقط؛ لا cron أو sender حي شُغّل في هذه المهمة، والرايةfalse.

## التفعيل المؤجل

1. مشروع Firebase خاص بمالك حق، تطبيق Android `com.haqfoundation.haq_app` وiOS `com.haqfoundation.haqApp`. لا نسخ مشروع Doctor Bike.
2. Android: وضع `google-services.json` في android/app على جهاز البناء فقط. iOS: إضافة GoogleService-Info.plist إلى Runner وCopy Bundle Resources، وتجهيز APNs P8 وTeam/Key ID داخل Firebase وتوقيع يدعم Push. الملفان مستثنيان من Git، ولا توجد ملفات إعداد وهمية.
3. حساب خدمة بصلاحية FCM الصحيحة وخدمة HTTPv1 مفعلة، وملف خاص خارجpublic/Git؛ RELIGIOUS_PUSH_PROJECT/RELIGIOUS_PUSH_CREDENTIALS، ثم migration المحدد والجدولة. الاستضافة تُراجع قبل تغيير أي قاعدة.
4. تفعيل RELIGIOUS_PUSH_ENABLED بالباك وHAQ_PUBLIC_PUSH_ENABLED في إعداد بناء Flutter عند اختبارStaging فقط. أول تشغيل للمرسل يحدد حد التفعيل؛ نشر رسالة جديدة بعده للاختبار، لا إعادة إرسال أرشيف.
5. بعد الانتقال المصرح للبناء: اختبار إذن رفض/قبول، Android/iOS foreground/background/terminated، نقر بارد ودافئ، إيقاف دون إنترنت ثم إعادة الاتصال، انتهاء/إخفاء قبل الإرسال، تجديد token/APNs وإعادة التثبيت، وحذف التطبيق. force-stop من إعدادات Android وقيود MIUI/شبكة/مزود قد تمنع الوصول؛ لا ضمان تجاوزها.

أدلة الاختبار: `test/public_push_test.dart` و`test/community_screens_test.dart`، وخمس حالات باك جديدة في ReligiousPushTest علىSQLite الذاكرة. الشبكة وFirebase/APNs محاكاة؛ لا دليل وصول Push حي. تفاصيل عدد المجموعة النهائية في سجل التنفيذ العام.
