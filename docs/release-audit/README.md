# تدقيق P13 المحلي

جرى ربط الميزات50 وحالات التصميم309 بالمصدر الحالي واختبارات الأقسام ودليل التنفيذ وبوابة التحقق المتبقية. لا تعديل للخطة/التصاميم الأصلية أو ادعاء تنفيذ كل لقطة كما هي؛ أجزاء الرئيسية والقرآن المحمية تعتمد التنفيذ الحالي المختبر.

- index.html: فهرس عربي قابل للبحث برمز الشاشة أو القسم.
- features.csv: صف مستقل لكل ميزة من50.
- design-states.csv: صف مستقل لكل حالة من309 مع مساري الفاتح والداكن.
- audit.json: التتبع الكامل ونتائج وجود الملفات وسجلي الاختبار وSHAآخر مصدر تطبيق مختبر.
- ../final-activation-checklist.md: قائمة الحسابات والمفاتيح والإعدادات والفحوص المؤجلة بقرار المستخدم.

لا مسار مصدر/اختبار/توثيق/صورة مرجعية مفقود في التوليد الحالي. مستوى الدليلsource_and_section_tests؛ ربط ملف اختبار بالقسم لا يثبت قبولًا بصريًا فرديًا لكل حالة ولا نجاح خدمة حية. release_ready=false عن قصد. آخرمجموعة كاملة312اختبارFlutter و89اختبارLaravel/1207تحققات في SQLiteالذاكرة المعزولة؛ لا تشغّل هذه الأداة اختبارًا أو تطبيقًا أوDBأوAPI.

لإعادة التوليد منPowerShell في مستودعFlutter، مرر المسارات الفعلية للمراجع والباك وسجلات اختبار ناجحة:

```powershell
python tool/release_audit.py --plan '<مجلد خطة التنفيذ>' --designs '<مجلد التصاميم المعتمدة>' --backend 'C:/laragon/www/haq-foundation' --flutter-log build/p12-final-full.log --backend-log C:/laragon/www/haq-foundation/storage/logs/p12-final-tests.log
```

الأداة تقرأGitHEAD وJSONوالسجلات وتتحقق من وجود الأدلة، ثم تكتب ملفاتها الأربعة داخل مستودعFlutter فقط. تفشل عند تغيّر الأعداد أو تكرار رموز الحالات أو نقص ملف أو غياب نجاح المجموعة في السجل. لا تدعي أن مجرد وجود الملف يثبت اكتمال جميع حالات سلوكه؛ لذلك بقيت بوابات الجهاز والخدمات والإطلاق منفصلة وموثقة.
