# بدء مراجعة P10 — 2026-10-26

توجد وحدة حساب ديني مستقلة بالفعل، وليست حساب موظف: register/login/profile/logout في routes/quran.php تحت v1/religious/account، وReligiousAccountOnly ورمز quran:sync. قارئ Flutter يستخدمها في quran_sync.dart وquran_account.dart، مع عزل الضيف والحساب وطابور المزامنة والخروج المحلي دون شبكة.

لم يظهر مسار Google ديني أو اسم مستخدم أو استرداد كلمة مرور/حذف حساب في العقد الحالي. لا ينبغي إنشاء حساب موظف أو الوثوق بمعرّف Google مرسل من العميل دون التحقق الخادمي. لم تُقرأ أسرار أو .env أو تُفترض معرفات OAuth.

المطلوب بعد P09: توسيع العقد والحساب باختبارات SQLite معزولة، توحيد لوحة حالة مزامنة القرآن والمحتوى والنشاط، ثم نسخ/استعادة ذات إصدار وبصمة ومعاينة قبل الاستبدال/الدمج، مع استثناء الرموز/الأسرار والتنزيلات الخام. إعدادات P08 والصلاة/الموقع في P09 محلية منفصلة لكل نطاق وتحتاج سياسة إدراج واضحة في النسخ؛ استيراد موقع لا يعني منح إذن الجهاز. Google والتحقق الحي يحتاجان إعدادات مشروع OAuth حقيقية قبل الادعاء بنجاح الدخول.

هذه مراجعة بداية؛ لا تنفيذ P10 أو تعديل قاعدة أو ترحيل أو نشر ضمن P09.
